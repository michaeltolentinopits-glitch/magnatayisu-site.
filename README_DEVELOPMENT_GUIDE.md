# MagnaTayISU: A Student-Centered Daily Step Tracking and Food Calorie Monitoring Application

**Platform:** MIT App Inventor 2 (https://ai2.appinventor.mit.edu)  
**Type:** Android Mobile Application | **Category:** Health and Lifestyle  
**Primary Users:** Isabela State University (ISU) Students  
**Storage:** TinyDB (offline, no internet required) | **Sensor:** Pedometer

> ⚠️ **Honesty Note for Defense:** Pedometer in MIT App Inventor counts steps **only while the app is open / screen is initialized** on most devices. It does NOT reliably count in background or when closed. Do not claim otherwise to your instructor. This guide implements the most reliable supported alternative: session steps + saved daily total merged without duplication.

## 3. TinyDB Data Design

**Namespace on every TinyDB: `MagnaTayISU_DB`** — if namespaces differ, screens cannot see each other's data. This is the #1 student bug.

| Tag | Type | Example | Purpose |
|---|---|---|---|
| `settings` | Dictionary | `{goal:8000, stride_cm:76, weight_kg:55}` | User settings |
| `food_db` | List of dictionaries | See CSV/JSON file | Food database (seeded on first run) |
| `food_entries` | List of dictionaries | See below | ALL entries all dates |
| `step_records` | Dictionary date→steps | `{"2026-10-20": 5420}` | Daily totals — stable date key, never list index |
| `achievements` | List of text | `["Goal Reached 2026-10-20"]` | Optional |
| `last_date` | Text | `2026-10-20` | Detect new day |
| `db_version` | Number | `1` | Avoid re-seeding food_db |

**Food entry structure (unique ID, never list position):**
```
make a dictionary
  id: join( Clock.Now instant formatted yyyyMMddHHmmss , random integer 100-999 )
  date: "2026-10-20"        (yyyy-MM-dd — sortable, unambiguous)
  meal: "Lunch"
  food_name: "Chicken Adobo"
  servings: 1.5
  unit: "cup"
  kcal_per_serving: 380
  total_kcal: 570           (= kcal_per_serving × servings, computed at save)
```

**ID rule:** Edit/Delete search the list for dictionary where `id = selected_id`. Never `remove list item at index` based on ListView position after filtering — filtered position ≠ stored position.

## 4. Global Variables (per screen, re-loaded from TinyDB on Initialize)

```
global todayDate, selectedDate, dailyGoal=8000, strideCm=76, weightKg=0
global allEntries=[], stepRecords={} (dictionary), foodDB=[]
global selectedFood={} , selectedEntryId=""
global sessionSteps=0, savedStepsAtStart=0, isTracking=false
```

In App Inventor there are no true cross-screen globals — **TinyDB is your shared state**. Every screen: `Initialize → LoadDailyRecords → UpdateDashboard/Refresh`.

## 5. Stage-by-Stage Block Logic (Exact)

### STAGE 1 — Structure & Design (Day 1)
1. Create project `MagnaTayISU`, create screens above, set colors per §1, set TinyDB namespace everywhere.
2. **Expected:** Navigation buttons open/close screens without stacking (always `close screen` on Back).
3. **Test:** Open/close each screen 5× — app must not slow or duplicate.

### STAGE 2 — Dashboard & Navigation

**Procedure `InitializeApp` (Screen1.Initialize):**
```
call LoadDailyRecords
call UpdateDashboard
set Lbl_TodayDate.Text to Clock.FormatDate(Now, "MMM dd, yyyy")
if TinyDB.GetValue("db_version", 0) = 0 → call SeedFoodDatabase; StoreValue db_version=1
check new day: if last_date ≠ today → Store last_date=today (do NOT delete step_records)
```

**Procedure `UpdateDashboard`:**
```
set today = FormatDate(Now,"yyyy-MM-dd")
steps = get value from stepRecords dictionary at today, default 0
set Lbl_StepsToday = join(steps, " steps")
pct = if goal>0 then round(min(steps/goal*100,100)) else 0
set Lbl_GoalProgressText = steps + " / " + goal + " steps (" + pct + "%)"
set Lbl_Distance = CalculateWalkingDistance(steps) + " km"
set Lbl_WalkCalories = EstimateWalkingCalories(steps) + " kcal burned (est.)"
foodTotal = CalculateDailyFoodTotal(today)
meals = count entries in allEntries where date=today (distinct meal values)
set Lbl_FoodCalories, Lbl_MealsCount
set Lbl_DailySummary = "You walked X km today and logged Y kcal from N meal(s). Goal: Z% reached."
```

**Navigation blocks:** `Btn_LogFood.Click → open another screen "FoodLog"` etc. On `Screen1.OtherScreenClosed → call UpdateDashboard` (auto-refresh after logging food — satisfies requirement).

**Test:** Change goal in Settings → return → dashboard % must change immediately.

### STAGE 3 — Food Database & Calorie Calculation

**Procedure `SeedFoodDatabase`:** Build list from `data/food_database.csv` content (18 items, §6). In blocks: create list of dictionaries manually OR store as list of lists `[name, category, unit, kcal, description]` — lists are easier in App Inventor than dictionaries for seeding. **Recommended student approach: list of lists, 5 items each.**

**Procedure `CalculateFoodCalories(kcalPerServing, servings)`:**
```
result = kcalPerServing × servings   (use math multiply block)
return round(result)
```

**Live preview:** `Txt_Servings.TextChanged` and `ListView_Foods.AfterPicking` →
```
if selectedFood empty → Lbl_CalcPreview="Select a food first"
else if Txt_Servings not numeric or ≤0 → "Enter servings greater than 0"
else Lbl_CalcPreview = "Estimated: " + CalculateFoodCalories(...) + " kcal"
```

**Search:** `Txt_SearchFood.TextChanged` → rebuild ListView elements: for each food in foodDB, if `contains(text=lowercase(food name), piece=lowercase(search))` add to filtered list. Empty search = show all.

**Procedure `AddFoodEntry`:**
Validation first (see §8). Then create entry dictionary/list with unique ID, add to `allEntries`, `TinyDB.StoreValue("food_entries", allEntries)`, Notifier `Entry saved`, refresh ListView_TodayLog + totals.

**Edit:** Tap entry in ListView_TodayLog → store selectedEntryId, show its values in inputs, Btn_AddEntry text becomes `Save Changes`. On save, find by ID and replace fields.
**Delete:** Select entry → Notifier.ShowChooseDialog `Delete this entry?` → on Choose, remove item with matching ID, save, refresh. **Confirmation is mandatory.**

**Meal subtotals:** Loop entries for today, accumulate 4 variables by meal value.

**Worked example to demo:** Cooked White Rice 200 kcal × 2 servings = **400 kcal** ✓

### STAGE 4 — Step Tracking & Goals

**Pedometer facts (verify on YOUR phone):** Component in Sensors palette. Events: `Pedometer.StepChanged (steps walked in session, distance)`, properties: `TotalSteps`? In current AI2 Pedometer exposes `WalkSteps` via StepChanged event parameter and `Distance`. **Check your AI2 version's blocks — do not copy property names blindly.** Use the event parameter, not polling.

**Anti-duplicate design (critical):**
```
StepTracker.Initialize:
  savedStepsAtStart = stepRecords[today] (from TinyDB, default 0)
  sessionSteps = 0
  isTracking = false

Btn_StartPause.Click:
  if not isTracking → call Pedometer.Start ; isTracking=true ; text="Pause"
  else → call Pedometer.Stop ; call SaveStepRecord ; isTracking=false

Pedometer.StepChanged (sessionStepsFromSensor):
  sessionSteps = sessionStepsFromSensor   // sensor already counts session cumulatively — DO NOT add it each event (+= causes duplication!)
  totalToday = savedStepsAtStart + sessionSteps
  update labels (distance, calories)
  call SaveStepRecordThrottled (save at most every 10 steps or on Pause/ screen close)

Procedure SaveStepRecord:
  stepRecords[today] = savedStepsAtStart + sessionSteps
  TinyDB.StoreValue("step_records", stepRecords)

Screen.Close / Back button: call SaveStepRecord BEFORE close screen.
```

> **Why duplicates happen:** (1) Adding event value on every StepChanged, (2) Pedometer on 2 screens, (3) Saving on Initialize again. The design above prevents all three. Explain this in defense.

**Sensor unavailable:** Wrap Start in Screen ErrorOccurred / check: if StepChanged never fires after Start, Lbl_SensorStatus = `Step sensor not detected on this device. You can still log food and view history.` Never crash, never fake steps. Provide **manual test input** labeled `Development only: simulate +100 steps` ONLY during testing — remove or clearly label before submission.

**ResetDailyTracking procedure:** Notifier confirm → `savedStepsAtStart=0, sessionSteps=0, Pedometer.Reset?` If no Reset block exists in your version: store `resetOffset = current total` and subtract it. Set stepRecords[today]=0. **Previous dates untouched** — test this.

**New day:** On Initialize, if today ≠ last_date: savedStepsAtStart = stepRecords[new today] = 0. Yesterday's record stays in dictionary.

### STAGE 5 — TinyDB Persistence & History
- Every mutation → immediate `StoreValue`. Every screen Initialize → `GetValue` with safe default (`""` → convert to empty list/dictionary if not a list).
- **History screen:** DatePicker sets selectedDate (format yyyy-MM-dd). `ChangeSelectedDate` procedure reloads entries/steps for that date only — read-only view, never writes.
- Test: log food on "today", change date picker to yesterday → list empties (correct empty state: `No records for this date.`), change back → records return.

### STAGE 6 — Daily Summary & Weekly Report

**Procedure `GenerateWeeklySummary`:**
```
totalStepsWeek=0, goalDays=0, daysWithData=0
for dayOffset 0 to 6:
  date = today minus dayOffset (use Clock.AddDays)
  s = stepRecords[date] default 0
  totalStepsWeek += s; if s>0 daysWithData+=1; if s>=goal goalDays+=1
avgSteps = if daysWithData>0 then round(totalStepsWeek/daysWithData) else 0
Display: "Last 7 days: X steps total • Average Y/day • Goal reached on Z day(s)"
+ per-day list: "Oct 20 — 5,420 steps — 1,150 kcal logged"
```
Keep consumed vs burned **separate lines**. Never show `consumed − burned = deficit`. Add caption: *Walking calories are only part of daily energy use, so this app does not compute a total calorie deficit.*

### STAGE 7 — Achievements (only after Stages 1-6 pass testing)
Check after each SaveStepRecord / AddFoodEntry: if steps≥goal and today's badge not in achievements list → add `Goal Reached yyyy-MM-dd`, Notifier. Streak: count consecutive days ending today with steps≥goal (or >0 — define one rule and document it).

Full protocol in `testing/TESTING_CHECKLIST.md`. Fix core bugs before polish.

## 7. Formulas & Accuracy Notes (Show in-app under `Lbl_Disclaimer`)

```
Distance (km) = Steps × Stride Length (m) ÷ 1000        [default stride 0.76 m, adjustable in Settings]
Walking Calories (kcal) ≈ Steps × 0.04                  [rough average for ~55-70kg adult]
   OR if weight entered: kcal ≈ Weight(kg) × Distance(km) × 0.53   — use this when weight available, document which one your build uses. Pick ONE and be consistent.
Food Calories = kcal per serving × servings
```
Label every output `(est.)`. Disclaimer text (copy into app): *"Calorie and distance values are estimates based on average serving sizes and stride length. Actual values depend on portion, ingredients, cooking method, body weight, and walking speed. This app is for general wellness tracking and does not provide medical or nutrition advice."*

## 8. Error Handling Table

| Case | Block Check | Message |
|---|---|---|
| No food selected | selectedFood empty on Add | `Please select a food first.` |
| Servings empty / 0 / negative / text | `is number?` + `>0` | `Enter servings greater than 0.` |
| Custom food kcal invalid | not number or ≤0 | `Enter a valid calorie value.` |
| Goal invalid | not number, <500 or >50000 | `Enter a goal between 500 and 50,000 steps.` |
| Sensor absent | No StepChanged / ErrorOccurred | Sensor status label (§ Stage 4) |
| Empty history | list length = 0 | `No records for this date.` |
| Delete entry / Reset day / Clear all | Notifier.ShowChooseDialog | Only proceed on `OK/Yes` choice |
| TinyDB returns empty string | `if not is list? value → set to empty list` | Prevents crash on first run |
| Duplicate StepChanged | Assign (=) not add (+=) sessionSteps | § Stage 4 |

## 10. Limitations, Extensions & Defense Q&A

**Limitations (state proactively):** ① Pedometer counts only while StepTracker screen is running — no reliable background counting in stock AI2. ② TinyDB is local only — no sync, uninstalling/clearing data erases records, data does not transfer between phones. ③ Calorie/distance values are estimates. ④ No user accounts — one user per device. ⑤ Food DB values are reference estimates, not laboratory measurements.

**Optional extensions (verify before use):** Chart extension / Canvas line chart for weekly steps (draw with Canvas.Line — built-in, no extension needed; recommended). Avoid extensions unless tested with your AI2 version; every extension must be documented with source + version.

**Likely instructor questions:**
- *Why didn't steps double when reopening?* → Session vs saved separation (Stage 4).
- *Why date as dictionary key?* → Stable ID, list positions shift after delete.
- *Why is there no calorie deficit?* → App measures only walking, not total energy expenditure (Basal Metabolic Rate, other activity).
- *Where does data live?* → TinyDB, offline, per-device.
